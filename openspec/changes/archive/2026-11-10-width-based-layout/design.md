# Design

## Context

- Раскладку сейчас выбирает сервер по User-Agent: `isDesktop()` в `src/server/device.ts`. Корневой `src/app/layout.tsx` оборачивает страницу в `DesktopFrame` или `PhoneFrame`. Главная, «Траты», «Пришли деньги», кошелёк и «Настройки» сами решают, какой экран отдать: телефонный или десктопный.
- Телефонная колонка — `Screen` из `src/components/screen.tsx`: `max-w-[430px]`, отступы 20 px по бокам и 56 px сверху (с safe-area). Все телефонные экраны собраны из неё.
- Меню разделов на телефоне рисует только `PhoneFrame` (`BottomNav`), и только на четырёх экранах разделов (`phoneMenuSection`). Колонка меню `max-w-[430px] px-5`, то есть само меню не шире 390 px.
- У форм есть десктопные варианты: `ExpenseForm variant="panel"`, `EnvelopeForm variant="panel" | "wide"`, `IncomeForm variant="desktop"`.
- `viewportFit: "cover"`: в альбомной ориентации iPhone контент может зайти под вырез экрана, если отступы его не учитывают. Сейчас этого не видно, потому что колонка 430 px стоит по центру.
- Тесты e2e: проект `iphone` (iPhone 13) и проект `desktop` (Desktop Chrome, 1440×1000), который запускается после него на тех же данных и проверяет десктопную раскладку.

## Goals / Non-Goals

**Goals:**

- Один набор экранов на всех устройствах. Ширина окна влияет только через CSS, сервер про устройство ничего не знает.
- Телефон шириной до 430 px выглядит ровно как сейчас.
- Проверки раскладки дохода и подсказки в форме траты, которые жили в десктопном прогоне e2e, остаются, но на телефонных экранах.

**Non-Goals:**

- Новые блоки или другой порядок блоков на широком экране. Только растягивание.
- Отдельные широкие макеты для «Трат», «Пришли деньги», кошелька и остальных экранов. Они следуют телефонным макетам и общему правилу растягивания.
- Изменения в расчётах, базе и данных.

## Decisions

### 1. Раскладка только через CSS, без определения устройства

Удаляем `isDesktop()` и все ветки по нему. Сервер отдаёт один и тот же HTML любому браузеру, ширина влияет через классы Tailwind.

Альтернативы:
- Отдавать обе раскладки и прятать лишнюю медиазапросом. Отклонено: десктопная раскладка уходит, прятать нечего.
- Определять ширину в браузере скриптом и перерисовывать. Отклонено: экран мигает при загрузке, серверный и клиентский HTML расходятся.

Побочный плюс: исчезает класс ошибок «эмуляция телефона в DevTools без перезагрузки», из-за которого раньше появлялось два меню. Тест на это в `e2e/navigation.spec.ts` остаётся.

### 2. Колонка экрана растягивается до 1180 px

`Screen` меняет ограничение и отступы:
- ширина контента: вместо `max-w-[430px]` — не больше 1180 px плюс боковые отступы, колонка по центру (`mx-auto`);
- боковые отступы: 20 px, от 600 px — 32 px, но не меньше safe-area слева и справа;
- верхний отступ: как сейчас (56 px или safe-area + 16 px), от 600 px — 32 px или safe-area + 16 px.

Граница 600 px и ширина 1180 px заводятся один раз: брейкпоинт в `@theme` в `src/app/globals.css` и значения в разделе «Размеры» `specs/02-экраны-и-дизайн.md`. Так они остаются дизайн-токенами, а не числами, разбросанными по экранам.

Экраны, которые рисуют колонку сами, без `Screen` (если найдутся при реализации), переводятся на `Screen` или на те же классы.

Альтернатива: отдельный брейкпоинт на каждом экране. Отклонено: правило одно для всех экранов.

### 3. Одна рамка с меню внизу

`PhoneFrame` становится рамкой приложения для всех (`AppFrame`), `DesktopFrame` удаляется. `phoneMenuSection` переименовывается в `menuSection`. `activeSection`, поле `paths` у разделов и вариант `layout="responsive"` у пункта меню нужны были только боковому меню и удаляются.

Нижний блок с меню (`BottomNav`) получает те же ширину и боковые отступы, что колонка `Screen`: до 1180 px плюс отступы 20/32 px, не меньше safe-area. Внутри:
- уже 600 px — как сейчас: колонка, «+» 60×60 над меню справа, меню на всю ширину;
- от 600 px — строка: меню растягивается (`flex: 1`), «+» справа шириной 64 px и высотой меню (растягивается по высоте строки, меню 64 px);
- уже 360 px — подписи пунктов скрыты визуально (`sr-only`), ссылка сохраняет имя для экранного диктора и для тестов.

Подпись пункта переносится сама: на телефоне «Пришли деньги» в две строки, в широком меню — в одну. Отдельного правила для неё нет.

Граница 360 px — ещё один брейкпоинт в `@theme` рядом с 600 px.

Альтернатива: меню шириной с телефон по центру. Отклонено пользователем: меню растягивается, как остальные блоки.

### 4. Экраны берут телефонную ветку

- Главная, «Траты», «Пришли деньги», кошелёк, «Настройки»: остаётся только телефонная ветка.
- Удаляются: `home-desktop.tsx`, `daily/daily-desktop.tsx`, `wallets/[id]/wallet-desktop.tsx`, `wallets/[id]/envelope-table.tsx`, `components/desktop.tsx`, `components/desktop-frame.tsx`, `components/category-progress.tsx`, `server/device.ts`.
- Формы теряют десктопные варианты (`variant` у формы траты, конверта и дохода). Кошелёк перестаёт читать `?envelope=` — это был выбор строки в десктопной таблице.
- `mainEnvelopes` и `MAIN_ENVELOPES` из `src/domain/priority.ts` и их тесты удаляются: требование «Главные конверты кошелька» уходит.

### 5. Тесты

- Vitest: тесты `mainEnvelopes` удаляются вместе с требованием. Тесты меню переименовываются вслед за `menuSection`.
- e2e: `e2e/desktop.spec.ts` заменяется на `e2e/computer.spec.ts`, проект `desktop` — на `computer`: тот же Desktop Chrome 1440×1000, запуск после `iphone` на тех же данных. Проверки:
  - широкое окно: один экран «Конверты», блоки 1180 px по центру, бокового меню нет; меню и «+» справа той же высоты вместе 1180 px; «Пришли деньги» в одну строку; «+» открывает экран новой траты; на «Пришли деньги» и «Настройках» меню с «+» тоже 1180 px;
  - окна 800 и 390 px на компьютере: блоки 736 и 350 px, меню внизу в одну строку; на 390 px «+» над меню;
  - окно 340 px: подписей в меню не видно, пункты находятся по имени;
  - кошелёк в широком окне: без меню, со стрелкой «назад», конверты по приоритету;
  - форма траты в широком окне: кнопка «Сохранить» 1180 px; подсказка «На жизнь останется» и сохранение, перенесённые из десктопного прогона;
  - раскладка дохода: нехватка с снятым кошельком и сохранением, кошелёк только с полными конвертами — перенесены из десктопного прогона, суммы те же;
  - «Настройки» через меню внизу: «Как установить на iPhone» и «Выйти».
- Сначала пишется `computer.spec.ts` и падает на десктопной раскладке, потом меняется код.

## Risks / Trade-offs

- [В окне 1180 px строки кошельков и трат очень длинные: название слева, сумма далеко справа] → Так выбрано на макете (вариант «одна колонка»). Если будет неудобно, ширину контента можно уменьшить одним токеном.
- [Поля форм шириной 1180 px] → Выбрано явно: формы растягиваются как всё остальное.
- [Меню на 1180 px: пункты по 270 px, значок и подпись далеко друг от друга по горизонтали] → Выбрано явно: меню растягивается как остальные блоки. Проверяется на скриншотах.
- [Без подписей в окне уже 360 px меню понятно только по значкам] → Значки те же, что на телефоне; диктор и тесты находят пункты по имени.
- [Альбомная ориентация iPhone: растянутый контент заходит под вырез] → Боковые отступы не меньше safe-area.
- [Блоки, которые на телефоне стоят по два в ряд (две карточки сверху в кошельке), в широком окне становятся по 590 px] → Приемлемо по правилу «растягивать»; на этапе реализации снимаются скриншоты всех экранов на 1440 px и показываются пользователю.
- [Удаление десктопных тестов ослабит проверки] → Проверки сценариев переносятся на телефонные экраны в широком окне, удаляются только проверки самой десктопной раскладки.

## Migration Plan

База и данные не меняются. Выкатка обычная. Откат — запуск предыдущего образа.
