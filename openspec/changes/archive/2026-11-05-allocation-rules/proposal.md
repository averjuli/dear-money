# Proposal

## Why

Меняется раскладка дохода. С каждого дохода уходит половина взноса. Излишек больше не уходит на повседневные траты. Когда денег не хватает, пользователь сам выбирает кошельки. Эти правила нужно закрепить в требованиях и сделать в приложении.

## What Changes

- **BREAKING** С каждого дохода в конверт уходит половина его взноса в месяц, будь то зарплата, аванс или другой доход. Остальное идёт на повседневные траты. Вид дохода на расчёт не влияет. Чип «Откладывать X ₽ в месяц» на главной показывает полную сумму за месяц, как раньше.
- **BREAKING** Излишек по-прежнему перетекает: взнос полного конверта уходит в самый важный неполный конверт кошелька. Но теперь он уходит туда целиком, даже если тот перевалит за потолок. Лишнее лежит в нём сверх потолка. Дальше по приоритету и на повседневные траты излишек больше не идёт.
- **BREAKING** Если в кошельке все конверты полные, каждый оставляет свой взнос у себя, сверх потолка. Раньше взносы такого кошелька уходили на повседневные траты.
- Если дохода не хватает на все взносы, на экране раскладки у кошельков появляются галочки, сначала отмечены все. Деньги идут только в отмеченные: по порядку кошельков, внутри — по приоритету конвертов.
  - Отмеченные помещаются в доход целиком — остаток идёт на повседневные траты.
  - Не помещаются — последний отмеченный получает часть, на повседневные 0, видно «Не хватает X ₽».
  - Если галочки не трогать, всё работает как сейчас.
- В требованиях закрепляется то, что уже работает:
  - при создании конверта в поле «копить на N раз» стоит 3;
  - порядок кошельков задаёт пользователь;
  - вход по логину и паролю из `.env`.
- Кошелька «Запасные» больше нет:
  - он уходит из демо-данных, тестов и сценариев;
  - и из файла с настоящими данными `data/my.local.json`;
  - «Всего в конвертах» по демо-данным становится 230 350 ₽.
- Описание продукта в `specs/01-продуктовая-идея.md` и `specs/02-экраны-и-дизайн.md` приводится к новым правилам, числа критерия успеха обновляются.

Не входит:

- «Осталось на жизнь» как остаток кошелька на жизнь, без дат зарплаты — отдельная правка.
- Округление взноса до 50 ₽ — отдельная правка.
- Удаление «Запасных» из уже заполненной базы — это делается в приложении, кнопкой удаления кошелька.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `income-allocation`: половина взноса с каждого дохода; излишек целиком у получателя, сверх потолка; полный кошелёк оставляет взносы у себя; выбор кошельков галочками при нехватке; новые числа в сценариях без «Запасных».
- `envelopes`: «Всего в конвертах» без «Запасных»; сценарий «меньше трёх конвертов» на другом кошельке; загрузка настоящих данных — 5 кошельков; «копить на N раз» по умолчанию 3 при создании конверта.

## Impact

- `src/domain/allocation.ts`: половина взноса, новое правило излишка, раскладка только по выбранным кошелькам. `src/domain/money.ts`: деление пополам с округлением, это единственный модуль, где округляем.
- `src/app/income/income-form.tsx`: галочки кошельков при нехватке, новые тексты карточек излишка и предупреждения. Обе версии, телефон и компьютер.
- `src/server/actions.ts` (`allocateIncome`): принимает список снятых кошельков и пересчитывает раскладку на сервере по ним.
- База и миграции не меняются.
- Данные: `data/demo-seed.json` и `data/sample-seed.json` без «Запасных». В `sample-seed` поправлена одна выдуманная стоимость, чтобы числа критерия успеха совпадали с демо-данными. `data/my.local.json` без «Запасных», в git файл не попадает.
- Тесты: доменные тесты раскладки, конвертов, приоритета и `sample-seed` на новых числах; e2e `main-scenario` и `desktop` на новых числах и без «Запасных»; новый e2e на выбор кошельков.
- Документы: `specs/01-продуктовая-идея.md` (описание излишка и раскладки, критерий успеха) и `specs/02-экраны-и-дизайн.md` (числа и порядок кошельков на главной, галочки и излишек на экране раскладки). Макеты в `design/` не трогаем.
