# Dear Money

Личный планировщик накоплений по методу конвертов. Откладываю деньги под редкие расходы, вижу, на сколько раз хватит каждого конверта, а остаток зарплаты идёт на повседневную жизнь.

- Идея и ограничения: `specs/01-продуктовая-идея.md`
- Экраны и дизайн: `specs/02-экраны-и-дизайн.md`, макеты в `design/`
- Требования фич: `openspec/specs/`
- Правила для Claude Code: `CLAUDE.md`

## Что в репозитории сейчас

Только спеки, макеты и стартовые данные. Кода ещё нет: его пишет Claude Code по плану ниже.

| Папка или файл | Что внутри |
|---|---|
| `specs/` | Продуктовая идея, экраны, дизайн-токены, открытые вопросы |
| `openspec/specs/` | Требования по фичам со сценариями и числами для тестов |
| `design/` | Макеты 7 экранов и наброски маскота Копи |
| `data/demo-seed.json` | Демо-данные: названия кошельков и конвертов как у меня, суммы выдуманные. Можно в git |
| `data/my.local.json` | Мои настоящие данные. Не в git |
| `.env.example` | Какие настройки нужны, без значений |

## План

Делаем по одной фиче. Каждая: ветка → требования из `openspec/specs/` → план → код с тестами → PR.

| # | Фича | Спека | Готово, когда |
|---|---|---|---|
| 1 | Каркас: Next.js, Postgres в Docker, дизайн-токены, `/health`, CI | - | Пустая страница с логотипом открывается, CI зелёный |
| 2 | Вход для одного пользователя | `auth` | Без пароля внутрь не попасть |
| 3 | Логика конвертов без экранов | `envelopes` | Все сценарии с числами проходят в тестах |
| 4 | Логика раскладки и излишка без экранов | `income-allocation` | Сценарии проходят, излишек 7 450 уходит в «Косметологию» |
| 5 | База и загрузка начальных данных | `envelopes` | Мои кошельки из `data/my.local.json` в базе |
| 6 | Главная и кошелёк | `envelopes` | Экраны 1, 5, 6 как в макете, перетаскивание работает |
| 7 | Пришли деньги | `income-allocation` | Экран 3, раскладка сохраняется |
| 8 | Траты | `expenses` | Экран 2, подсказка-последствие |
| 9 | Повседневные траты | `daily-spending` | Экраны 4 и 7 |
| 10 | PWA и выкатка на VPS | - | Открывается на поддомене, ставится на экран «Домой» |

Пункты 3 и 4 самые важные: это логика, ради которой приложение и делается. Её проверяем тестами до того, как рисовать экраны.

## Запуск на компьютере

Нужны: Node.js, pnpm, Docker.

```
cp .env.example .env               # заполнить строки базы (POSTGRES_*, DATABASE_URL)
docker compose up -d db            # Postgres на 127.0.0.1, порт из POSTGRES_PORT
pnpm install
pnpm db:migrate                    # таблицы в базе
pnpm auth:setup                    # спросит логин и пароль, запишет в .env хеш и секрет
pnpm db:seed data/sample-seed.json # тестовые данные: 5 кошельков, трат нет
pnpm build && pnpm start           # http://localhost:3000
```

- `pnpm auth:setup` запускать в обычном окне терминала: пароль вводится скрыто и в `.env` попадает только его хеш
- Свои данные: `pnpm db:seed data/my.local.json`. Повторная загрузка не создаёт дублей и не перезаписывает то, что изменено в приложении
- `data/demo-seed.json` - демо-данные для тестов; `data/sample-seed.json` - тестовые данные для ручной проверки, на них сходятся числа из критериев успеха. Суммы в обоих файлах выдуманные

## Проверки

```
pnpm test        # логика расчётов и вход (Vitest)
pnpm test:e2e    # главный сценарий в браузере на отдельной базе dear_money_e2e (Playwright)
pnpm lint
pnpm typecheck
pnpm format:check
```

Перед `pnpm test:e2e` нужна сборка `pnpm build` и запущенный Postgres. Первый раз: `pnpm exec playwright install chromium`.

## Выкатка

Тот же VPS, что у CRM и лендинга, свой поддомен и своя база. Merge в main → CI собирает образ → на сервере миграции → новый образ → проверка `/health`. Подробности появятся в `deploy/` на фиче 10.

Что делаю сама: выбираю поддомен и добавляю запись DNS, кладу `.env` на сервер.
